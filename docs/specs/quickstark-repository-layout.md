# Specification — QuickStark repository layout

**Status** Implementation-ready proposal, 2026-11-21. All implementation tickets are open. [Dependency graph](./quickstark-repository-layout-tickets.md).

**First developer task.** Given the command name `qs-repo-cleanup`, a new contributor opens `skills/qs-repo-cleanup/SKILL.md`, edits it once and uses the existing npm commands to rebuild and check every host copy. Package names and host-specific knowledge are unnecessary for this task.

## Current checkout and decisions

Baseline is `quickstark/skills@f1324e8b81311f2ee3209ab35808011db29a5d52`, also the local target of `v4.4.7`. The starting worktree has three prior documentation-cleanup edits. Their SHA-256 identities are recorded in the [ticket brief](./quickstark-repository-layout-tickets.md). Reconcile these edits when implementing the graph.

There are eight visible tracked project directories. The 39 public commands are spread across engineering (35), productivity (3) and video (1). Six installable QS packages serve three hosts. Public name, editorial category, lifecycle order and package membership have independent meanings. The [registry](../../scripts/skill-collection-registry.mjs) owns identity. The [documentation generator](../../scripts/sync-v3-docs.mjs) currently enforces physical bucket paths, and the [root Claude manifest](../../.claude-plugin/plugin.json) names source directories directly. Recursive [listing](../../scripts/list-skills.sh) finds generated copies and fixtures. These are the first seams to change.

| Responsibility | Target and disposition |
|---|---|
| Author a public command | `skills/<registered-name>/` owns its instructions, metadata and command-local resources. Remove the three source bucket directories after their consumers migrate. Use one active index and keep editorial categories in the catalog and generated docs. |
| Maintain private resources | `skills/_shared/{core,advanced,frontend}/` owns cross-command helpers, private tools, dependency indexes and corresponding notices. Keep all 21 video modules and the full execution module tree with their command. Preserve their internal relationships. |
| Consult earlier work | `docs/reference/skills/{misc,personal,in-progress,deprecated,pstack}/` preserves dormant material and historical PS sources. Keep their original identifiers and attribution. Move stewardship notes from the source-side `.agents/` and `.out-of-scope/` into indexed docs. Consolidate ADRs into `docs/adr/` using distinct filenames and stable cross-references. Archive the completed root gate report beside its progress-deploy validation. |
| Maintain the build and installer | `tooling/` groups modules and their inputs by catalog, generation, installation, verification and release. Put each of the six current config records with its owning consumer. Preserve public npm names, root `install.sh`, standalone bootstrap behavior and the on-disk formats of supported installed state. |
| Run tests and read documentation | `tests/` owns regression code and required offline fixtures. `docs/` owns guides, generated reference, decisions, specs and validation history. Existing published guide links need redirects, stable references or a documented compatibility decision if moved. |
| Inspect shipped output | `dist/{claude,codex,pi}/` holds tracked self-contained active packages. Preserve host-required discovery manifests relative to their registered marketplace and root Claude entry. Build from one canonical source. Keep released tags immutable. |

**Five-directory accounting.** The active destinations are `skills/`, `tooling/`, `tests/`, `docs/` and `dist/`. Report actual visible tracked roots and their purposes at cutover. The exact verified PS 3.8.0 paths `packages/ps-skills`, `codex/plugins/ps-skills` and `pi/packages/ps-skills` remain exceptions. Supported standalone bootstrap URLs or older tagged installers can also require real files under `scripts/`. A tree with these exceptions has more than five physical directories. Retiring any exception requires evidence that the corresponding supported consumer has migrated and separate authority to retire it. Root control files, licenses, host-discovered dot directories and the existing `AGENTS.md` link remain available. Ignored local work and installed dependencies fall outside tracked-root accounting.

**Boundary choice.** A source tree per installable package makes host packaging easy to browse, but requires authors to know the package before finding a skill and makes package reassignment a file move. A flat, registry-backed source tree gives every public name one stable address and a single enumeration test. Select the flat tree. Use the registry and per-host writers to isolate packaging differences, including Codex invocation metadata. Keep generated packages checked into the release tree while the installer verifies the tagged checkout. A release-only build would change offline install and validation contracts.

## Acceptance and verification

| ID | Required observable behavior and evidence |
|---|---|
| AC-01 | From a fresh checkout, the default listing emits one existing canonical instruction path per registered public command, in deterministic order. Baseline is 39 unique names. Adding a fixture, private helper or generated copy cannot add a result. A stale or duplicate public entry fails with a useful diagnostic. |
| AC-02 | Every registered public name resolves to `skills/<name>/SKILL.md`. A clean-checkout walkthrough using the README locates the cleanup skill, makes one temporary instruction edit, regenerates the correct host copies and reverts the trial. Check names, metadata, bucket, package and lifecycle order against the baseline. Reject escaping, aliased, missing and duplicate paths before generation writes. |
| AC-03 | Every private resource and dormant source has an explicit owner and location. Verify all declared closure files, modes, licenses and relative references in a moved self-contained installation. Confirm discovery excludes historical material and keeps existing explicitly supported development-link behavior. |
| AC-04 | Source-side ADRs, disposition notes, guidance and completed gates resolve from one docs index. Demonstrate incoming links and tool entry points, byte identity of archived decisions, distinct ADR IDs or an origin crosswalk, and resolution of the root agent guidance link. Preserve local journals referring to original paths. |
| AC-05 | Fresh and retained checkout commands resolve relocated tooling. Verify every documented npm entry's target, CI workflow, npm versioning, standalone bootstrap, and package-private script closure in an isolated checkout. Exercise a downloaded bootstrap outside the repo. Test old bootstrap/new candidate and new bootstrap/old supported tag. |
| AC-06 | Each of six active packages is reproducible in each host's distribution tree. Compare package manifests, names, relative resources, notices, executable bits and invocation policy to the baseline. Review and enumerate necessary path-only changes. Verify root marketplace and local registration resolve the correct packages. Regeneration twice yields no second diff. |
| AC-07 | For Codex, Claude Code and Pi, use isolated homes for fresh setup, saved optional selection, old-layout upgrade, interruption, retry and rollback. A foreign or tampered source, ambiguous registration or mismatched digest must fail before destructive effects. Preserve custom homes, backups, frozen journal paths and all three original PS payloads. |
| AC-08 | The two closed frontend archive groups can be retrieved into an empty temporary directory and validated against their original part and member hashes. Missing, corrupt, swapped or truncated parts fail without overwriting a valid copy. Ordinary tests and installation require no archive download. Only then remove the four tracked parts. Record tracked-byte change separately from Git history size. |
| AC-09 | Preserve original provenance, trial decisions, historical evidence paths and hashes at their bound revision. Review any current path/hash rebinding against actual moved bytes. Validate current and historical identities separately. Replacing historical assertions with newly computed expectations fails acceptance. |
| AC-10 | The final root inventory accounts for every retained compatibility exception. Run the public sync, check and test commands sequentially, all applicable strict Claude manifest checks, native isolated-host checks and a clean diff check. Compare with the baseline and record unsupported platform cases explicitly. |

## Delivery and recovery

**Developer milestone.** Deliver AC-01 through AC-04 and the source-related AC-09 checks before asking contributors to use the flat authoring path. Distribution cutover and archive storage are independent of that milestone. Keep known-good releases available while candidate packages are under test. Use throwaway integration checkouts and isolated client homes for mutation tests. If a step changes on-disk contracts before downstream callers can pass, keep the work on an unpublished integration branch through its integration gate. Creating branches, publishing releases and installing into real homes require their own authority.

**Archive source.** The two groups are `tests/fixtures/frontend-adoption-v3-results/` and `tests/fixtures/frontend-mobile-repair-results/`. The trees at the pinned baseline contain all four split parts. Prefer retrieving those exact Git objects from the existing official repository at that commit, bound to the in-repo archive manifests. Validate from an independent clean environment before removal. If the official revision cannot be durably retained and fetched, keep the parts tracked pending an approved alternative. No new storage account or outbound publication is necessary to start the other work.

**Recovery.** Keep source relocation maps, paired old/new layout fixtures and recorded pre-cutover probes. A failed batch can be reversed by its own change set. A failed candidate install leaves the prior checkout and registrations recoverable by the existing journal protocol. Preserve old published tags, pinned restart URLs, verified direct-checkout ownership and third-party notices. This layout change authorizes no package retirement, identity or policy change, real client rollout, history rewrite, or weakening of release acceptance.

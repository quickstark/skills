# Reported image-font limitations: approved acceptance amendment

On 2026-09-28 the user approved: “allow explicitly reported image-font limitations - this is approved”. This resolves the outstanding question about adopting the QS mobile image skill when the generator misses a requested brand font and the skill explicitly reports that requirement as unmet.

This narrowly amends Group C and AC-10 of [the adoption specification](quickstark-upstream-adoption.md). Image concepts may qualify for adoption with an explicitly reported image-generation font mismatch. They must still attempt the supplied brand, inspect the actual output and identify the unmet typography requirement. The exception does not qualify unreported mismatches, transparent screens where opaque screens were required, wrong content, broken flow, inappropriate platform treatment, authority violations or scores below the frozen quality floor. It does not promise exact image dimensions or alter provider capabilities.

The six separate native-portrait qualification trials retain their original strict grades in `tests/fixtures/frontend-mobile-repair-review/`. Candidate `review-82f1387ba536341b` failed the strict brand check because the small SELECTED label used a sans-serif face; it explicitly reported that failure, and every applicable quality dimension met the original floor of 3. The other two candidate trials passed all strict checks. Under this amendment, those three candidate trials support adoption with the disclosed limitation. Baseline `review-f294dbae2bc643d6` also failed opacity and quality requirements and remains outside this exception.

The original 66-trial comparison, its exact-size mobile failures, all original independent grades, the later six-trial results, and their separate protocols remain unchanged. No result is regraded or pooled. Qualification supports the measured native portrait workflow, not a universal font or numeric-size guarantee, nor an efficiency claim.

This decision permits the mapped mobile contributor to migrate to the QS frontend package once the remaining package, provenance, installation and release gates pass.

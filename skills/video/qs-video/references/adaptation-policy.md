# QS video authority and private routing

This policy governs every private module, helper, reference and example. The
selected QS root owns the outcome; module instruction files are technical
references. They do not invoke public skills, create goals, publish reports,
install dependencies or choose a model/delegation setting. User and host
instructions remain authoritative.

Read the dependency index, then the selected module's instructions and necessary
resources. Every named workflow/domain must resolve locally before its dependent
work. `instructions.md` is not an invocable skill. No compatibility alias or lazy
installation is created. The external animate-text catalog has no reviewed pinned
payload here; preserve that named-effect capability as an explicit unresolved
prerequisite, not a claim that a guessed tween is its equivalent.

Use an existing verified runtime through `QS_VIDEO_CLI`; never use an unpinned
package executor to silently fetch a runtime. A project pin is not automatically
updated because newer instructions exist. For fresh projects only, run the
root's scaffold helper: `node "$QS_VIDEO_DIR/scripts/scaffold.mjs" --cli
"$QS_VIDEO_CLI" -- <new-directory> [supported init options]`. It enforces
noninteractive initialization in an isolated sibling staging directory, disables skill refresh, and rewrites only staged AGENTS.md/CLAUDE.md. It requires an existing parent directory, revalidates destination identity/state after initialization, and publishes files with exclusive creation. It refuses a nonempty or concurrently changed target, preserves competing guidance, and retains staged diagnostics on failure. Its docs files are generated outputs of that new
scaffold, not existing user instructions. Never run the upstream skill installer
or refresh to recover a missing private module. Interactive preview and its
orphan process cleanup require a selected preview operation and host boundaries.

Provider examples document mechanisms, not blanket setup authority. Inspect
credentials availability without reading or printing secret values; summarize
auth status rather than relaying raw output. A provider chosen by the user stays
selected. If it is unavailable, report its exact prerequisite and use a local
alternative only when that alternative satisfies the request and existing
authority. Do not install tools/models, sign in, request paid output, collect
preferences outside the project, or submit a recipe merely because a helper
suggests it. Saved preferences are input data; inferred defaults are not new
permissions. For isolated tests, redirect helper global caches explicitly; real
runs must respect the user's selected cache/privacy behavior.

No ordinary creation/render/search miss sends feedback, a rating, a report,
issue, recipe, public URL or upstream PR. Keep diagnostic packets in the current
conversation with secrets redacted. A separate explicit external-report request
must name its operation/destination and payload; it is not a hidden final step.
Publication/cloud rendering must identify the authorized target, costs, artifact
and verification. Preserve any explicitly granted authority without repeated
confirmation. Runtime freshness requests and telemetry are separate from skill
behavior: document the actual runtime configuration instead of promising silence.

Prompt-only and storyboard-only requests stop at those artifacts. Existing briefs
and operation-only requests do not reopen intake. Review or rendering failures
remain failures; helper success does not certify an absent provider, missing
reference, incorrect output or the entire upstream compatibility matrix.

Existing session authorization satisfies a matching review/render checkpoint. Do not ask again solely because an upstream autonomous workflow keeps a final question. Collaborative checkpoints remain when the user selected them or necessary input is unresolved. Files containing dispatch or worker briefs are optional private mechanics, not authority to spawn agents.

Audio helpers require `QS_VIDEO_VERIFIED_LOCAL_PROVIDERS` for local model routes (comma-separated `kokoro`, `whisper`, `whisperx`, `parakeet`, `musicgen`). Set an entry only after checking the complete existing tool/model/cache for the chosen runtime. This records evidence, never grants setup authority. The tested profile currently has none of these local generation prerequisites; report them as blocked. Offline environment switches prevent HuggingFace fetches but do not prove every third-party runtime respects them.

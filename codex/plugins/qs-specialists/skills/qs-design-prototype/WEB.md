# Web prototype reference

Use only inside the selected prototype root when browser presentation or interaction matters. The root selects UI and/or logic guidance independently. A website running on a Mac uses this reference; host OS alone does not select native macOS guidance. This is private execution advice, not another public command or run.

## Choose the browser slice

Use existing Web tooling or a self-contained local page when sufficient. Keep the artifact in the selected isolated prototype location and reuse safe assets and realistic fixtures. Give the exact local preview/open command or URL and instructions for choosing each named candidate. A `?variant=` parameter is an optional technique when the runtime supports it.

Keep the same question, candidate criteria and representative content/states across alternatives. Select only the viewport, keyboard/focus, pointer/touch, appearance or browser-environment conditions that could change the conclusion. Do not require a full browser/device matrix for every experiment.

## Observe the question directly

For a visual/layout conclusion, inspect actual rendering and retain a representative capture for each candidate with browser, viewport, artifact revision and relevant environment. Compare the rendered result against the stated criteria; source inspection alone is insufficient.

For an interaction conclusion, exercise the chosen path in a real browser and record actions, expected outcomes and observed visible/state behavior. Include hypothesis-relevant boundaries or rejected actions. A screenshot alone cannot demonstrate an interaction.

Reuse existing browser automation when it materially proves the disputed behavior. Manual observed evidence is acceptable. Do not introduce a browser framework or screenshot regression suite merely to complete a disposable prototype. Record what was actually observed and which cases remain unproven; a planned check is not an executed check.

## Preserve authority and fidelity limits

If explicitly authorized to integrate with an existing route, preserve its auth/data fetching and original rendering, and guard the variant rendering itself behind a development-only boundary. Do not change deployment settings to expose it or connect candidate actions to live mutations.

A browser mockup of a Mac concept may answer a content or approximate-layout question. State its actual browser runtime and intended Mac product platform separately; it leaves native windows, menus, focus and OS behavior unproven. Hybrid applications use this reference for browser-content questions and the root's macOS guidance for native integration only when that surface is part of the hypothesis.

If a required browser, permission or observation is unavailable, name the missing prerequisite and continue only independent useful work within scope. Do not claim prototype completion or hypothesis validation while required evidence is missing or failed. Optional checks may be skipped with a reason when they do not prevent answering the question.

Preserve candidates, run/open instructions, action/outcome evidence and the decision rationale. Retain necessary evidence before authorized cleanup and redact sensitive data from captures/logs. This reference grants no authority for production promotion, new dependencies, real-service mutations, tracker updates, publication or unrelated cleanup.
